# Server Audit

Аудит Linux-сервера с цветным выводом и поддержкой Docker и k3s.
Результаты сохраняются в Markdown и JSON. Скрипт не устанавливает пакеты,
не меняет firewall и не перезапускает службы. Внешней телеметрии нет;
при наличии k3s используется локальная конфигурация доступа к Kubernetes API.

## Установка и запуск

Требуются Linux, Bash и Python 3.9+. Лучше всего поддерживаются Ubuntu/Debian.
Консоль на русском, часть диагностических пояснений на английском.

```bash
git clone https://github.com/escanderm/server-audit.git
cd server-audit
sudo ./audit.sh
```

Если Python отсутствует или старее 3.9, `audit.sh` остановится и покажет команду
установки для обнаруженного пакетного менеджера. Ничего автоматически не устанавливается.
Для Ubuntu/Debian:

```bash
sudo apt-get update
sudo apt-get install -y python3 python3-apt
```

После установки повторите запуск. Если отсутствует только `python3-apt`, скрипт
выведет подсказку и продолжит остальные проверки. В старых дистрибутивах пакет
`python3` может быть старее требуемой версии; проверьте `python3 --version`.

Root нужен для чтения SSH-конфигурации, firewall и журналов. Без необходимых прав
или утилит проверки получают статус «Не проверено». Зависимости автоматически
не устанавливаются. Для проверки пакетов нужен системный модуль `python3-apt`.

## Отчёты

Каждый запуск создаёт отдельную папку внутри проекта:

```text
reports/
  20261123-120000-<случайный-суффикс>/
    report.md
    report.json
```

`reports/` включена в `.gitignore`. Права папок 0700, файлов 0600.
Путь выводится в терминале. После запуска через sudo отчёты принадлежат root;
читать их можно через `sudo less`. Общедоступная папка или симлинк в пути отвергаются.
Отчёты содержат сведения о сервере и сети, публиковать их стоит после проверки.

Другую папку можно указать явно:

```bash
sudo ./audit.sh --output /var/log/server-audit
```

## Проверки

- Эффективные настройки SSH через `sshd -T`.
- TCP/UDP-сокеты: loopback, частные, глобальные и wildcard-адреса.
- UFW, цепочка FORWARD, глобальные IPv6-адреса.
- Перезагрузка, диск, память через MemAvailable, нагрузка и сбои systemd.
- Кандидаты обновлений APT, security-репозитории, таймер и ошибки APT.
- Записи sudo без сохранения команд, состояние SSH jail Fail2ban.
- SUID-файлы корневой файловой системы и принадлежность пакетам dpkg.
- Публикации Docker и Kubernetes Services/NodePort/LoadBalancer.
- hostPort, hostNetwork, привилегированные поды, готовность подов и история CronJob.

Секреты Kubernetes, переменные контейнеров и приватные ключи не читаются.
Количество портов и сервисов само по себе не считается уязвимостью.

## Оформление и параметры

```bash
sudo ./audit.sh --skip-suid
sudo ./audit.sh --color always
sudo ./audit.sh --color never
```

Цвета включаются автоматически в терминале. `NO_COLOR=1` отключает автоматическое
окрашивание. При перенаправлении в файл ANSI-коды по умолчанию не добавляются.
На узком экране таблицы раскладываются по полям. Длинные имена не обрезаются.
Markdown/JSON сохраняют полные данные без цветовых кодов.

| Статус | Значение |
| --- | --- |
| ОК / PASS | Конкретная проверка пройдена |
| ВНИМАНИЕ / WARN | Нужна оценка или обслуживание |
| ПРОБЛЕМА / FAIL | Обнаружено конкретное опасное свойство |
| НЕ ПРОВЕРЕНО / UNKNOWN | Недостаточно данных или проверка недоступна |
| ИНФО / INFO | Инвентаризация и контекст |

Код возврата: 2 при FAIL, 0 иначе. Код 0 не означает, что все проверки пройдены:
WARN и UNKNOWN нужно смотреть в консоли или JSON.

## Доступность портов извне

Проверка выполняется только по явному запросу; работает и на macOS:

```bash
python3 audit.py --probe example.com --ports 22,80,443,5000,6443,8090,10250
```

Для проверки извне запускайте команду за пределами сети проверяемого сервера.
LAN и NAT loopback не подтверждают доступность из интернета. Выполняется только
TCP-соединение без авторизации и эксплуатационных запросов. UDP и настройки
роутера не проверяются.

## Ограничения

Это аудит состояния и конфигурации, не сканер CVE и не доказательство отсутствия
взлома. Статус UFW не доказывает защиту контейнерного трафика. Отдельные SSH
Match-контексты не проверяются. Владение файлом со стороны dpkg не доказывает его
целостность. Поиск SUID исключает контейнерные слои, /snap и другие файловые системы.

Кэш APT автоматически не обновляется. Ошибки за последние 24 часа могут оставаться
в отчёте после исправления причины. Успех задания бэкапа не заменяет проверку
восстановления. На дистрибутивах без APT/UFW часть проверок недоступна.
